# Claude Code에 보낼 메시지 — 캐릭터·무기·차량 Blender 사실화 패스

## 역할과 목표
너는 cyber-rpg의 **캐릭터·하드서피스 테크니컬 아티스트**다. 화면에 나오는 모든 "모델"을 **Blender로 만들어** 사실적으로 바꾼다.
대상: 플레이어 캐릭터, 행인 NPC, 적(인간형·보안 로봇·드론), 1인칭 팔(일반 + 사이버웨어 팔 4종), 총 12종, 차량, 사이버웨어 부품.
목표 품질: 레퍼런스 사진 속 행인과 차처럼 **사실 비율·사실 재질**. 단, 다른 게임의 캐릭터·인물·브랜드 디자인은 절대 베끼지 않고, **실존 인물의 얼굴도 만들지 않는다.** 전부 자체 디자인이다.

## 0. 절대 규칙
- 답은 항상 한국어로 한다.
- `cyber-3v3.rbxl`은 절대 저장하지 않는다. `rojo build -o cyber-rpg.rbxl`은 실행하지 않는다. computer-use는 쓰지 않는다.
- Studio 확인은 네가 직접 한다(연결된 Studio 연동 도구). 손맛, 모바일 실기기, 다인원 플레이만 나에게 묻는다.
- 기능 브랜치에서만 커밋한다(예: `blender-characters`). 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙인다.
- 단계마다 `~/.rokit/bin/lune.exe run tests/run.luau`가 전부 통과해야 한다.
- 키즈 규칙(처치 표현)은 Phase 0 결정을 따른다. 사실적인 사람을 만들어도 사실적인 피·상처는 넣지 않는다.

## 1. 파이프라인 (자동화가 핵심)
모든 모델은 **재현 가능한 스크립트**로 만든다. 손으로 한 번 만들고 끝나는 파일을 만들지 않는다.

```
tools/blender/
  common/            공용: 단위·축 변환, 네이밍, 검증, 내보내기
  humans/            사람 생성(MPFB2), 옷 입히기, 리그, LOD
  hardsurface/       총·사이버웨어·로봇·드론·차량 절차 모델링
  bake/              노멀·AO·곡률·발광 마스크 굽기, 텍스처 패킹
  validate.py        로블록스 규격 검사(아래 표)
  manifest.json      에셋 목록: 이름 / 소스 스크립트+시드 / 파일 / 업로드 ID / LOD ID / 삼각형 수
```

- 실행: `blender --background --python tools/blender/... -- <인자>`. 같은 시드면 같은 결과가 나와야 한다.
- 내보내기: FBX 또는 glTF. **단위·축·스케일을 먼저 실험**해서 캐릭터 키가 로블록스에서 ≈5.5스터드가 되는 설정을 찾고 `common/`에 고정한다.
- 업로드: Open Cloud Assets API로 **Model**(FBX/glTF) 업로드를 쓴다. API 키는 내가 환경 변수로 넣는다. 지원 형식과 제한은 작업 전에 공식 문서로 다시 확인한다.
- 게임에서 불러오기: 코드에는 **에셋 ID만** 두고 런타임에 불러온다(예: `InsertService:LoadAsset`, 또는 메시만 필요할 때 `AssetService:CreateMeshPartAsync`). 둘 중 Rojo 구조와 스트리밍에 맞는 방식을 실험해 정하고 보고한다.
- **애니메이션 업로드**: Open Cloud의 애니메이션 업로드는 제한이 있다(로블록스 고유 형식 재업로드 위주). 그래서 이렇게 한다.
  1. Blender 동작을 KeyframeSequence로 변환해 Studio에서 재생 테스트(`AnimationClipProvider`의 임시 등록 등)를 한다.
  2. 실제 게임용 게시가 사용자 클릭 없이 안 되면, **한 번에 묶어서 게시할 수 있게 준비**한 뒤 나에게 "몇 번 클릭하면 되는지" 요청한다.

### 로블록스 규격 검사 (`validate.py`, 모든 에셋 필수)
| 항목 | 기준(작업 전 공식 문서로 재확인) |
|---|---|
| 메시 하나당 삼각형 | ≤ 20,000(넘으면 부위별로 나눈다) |
| 정점당 본 영향 | ≤ 4 |
| 본 | 스케일 1, 회전 0으로 고정(frozen), 이름 규칙 준수 |
| 텍스처 | PBR 4종(Color/Normal/Roughness/Metalness) + 필요 시 발광 마스크, 해상도는 확인된 최대치 이하 |
| 플레이어 바디 | 로블록스 아바타 바디 규격(R15 부위 구조, 본 이름, 어태치먼트, 레이어드 클로딩용 케이지) |
| LOD | LOD0/1/2(+원거리 임포스터)가 모두 있어야 통과 |

## 2. 사람 (플레이어·행인·인간형 적)

### 2-1. 몸과 얼굴
- **MPFB2**(MakeHuman Blender 플러그인)로 만든다. 생성 결과물은 **CC0**라 게임에 써도 된다. 플러그인 자체는 GPL 계열이니 **플러그인 코드는 저장소에 넣지 않고**, 설치는 나에게 요청한다.
- 파라미터(성별, 나이 20~60, 체형, 키, 근육, 피부톤, 얼굴형)를 시드로 뽑아 **행인 30종 이상**을 만든다. 실존 인물을 닮게 조정하지 않는다.
- 피부: 로블록스에는 피하 산란(SSS)이 없다(2027년 개선 예정 발표만 있다). 그래서 다음으로 보정한다.
  - 알베도에 아주 약한 붉은 기를 미리 넣는다.
  - 모공·주름은 노멀맵으로 넣는다.
  - 러프니스로 T존·입술·눈가 차이를 준다.
- 눈: 각막과 홍채를 분리한 별도 메시로 만든다. 러프니스를 낮춰 반짝이게 하고, 사이버 안구 변형(빛나는 홍채)은 발광 마스크로 한다.
- 머리카락: 알파 투명은 정렬 문제가 생긴다. 그래서 **불투명 볼륨 메시 + 가장자리만 알파 테스트**로 만든다. 사이버펑크풍 스타일(언더컷, 버즈컷, 포니테일, 염색) 10종 이상.
- 불쾌한 골짜기(uncanny valley)를 피한다. 표정 없는 얼굴이 가장 어색하니 행인에게 눈 깜빡임과 미세 움직임을 넣는다. 대화 NPC는 FACS 얼굴 애니메이션(FaceControls)을 검토한다.

### 2-2. 옷과 크롬
- 옷: MPFB2 CC0 의상을 바탕으로, Blender에서 사이버펑크풍 의상을 직접 모델링한다(오버사이즈 재킷, 테크웨어, 방수 코트, 작업복, 정장, 스트리트웨어, 경찰·보안 제복 자체 디자인). 천 시뮬레이션으로 주름을 잡고 노멀맵으로 굽는다.
- 재질 대비: 가죽, 나일론, 데님, 반사띠, 발광 라인(발광 마스크).
- **사이버웨어 부품**: 기계 팔·다리, 얼굴 임플란트 선, 목 뒤 포트, 광학 안구. 하드서피스로 모델링하고 몸에 붙는 형태로 만든다. "크롬 부품 이탈" 처치 연출이 가능하도록 **분리 가능한 부위**로 만든다.
- 조합: 몸 × 옷 상의/하의/신발 × 머리 × 크롬 × 색 변형으로 **보이는 행인 조합 수백 가지**를 만든다.

### 2-3. 플레이어 캐릭터
- `StarterCharacter`로 사실형 캐릭터를 쓰되, **로블록스 아바타 바디 규격**에 맞춘다. 그래야 Humanoid 물리, 기본 애니메이션, 레이어드 클로딩이 동작한다.
- 1인칭이라 본인은 팔만 주로 보이지만, 다른 플레이어에게는 전신이 보인다. 그림자에도 비친다.
- 사이버웨어 진화 단계에 따라 몸의 크롬 부품이 바뀌게 한다(데이터 연동).

### 2-4. 애니메이션
- 출처: ① CMU 모션 캡처 데이터베이스(자유 사용) ② Blender에서 직접 키프레임 ③ 내가 따로 받아 주는 파일. 어떤 출처든 `manifest.json`에 적는다.
- 리타깃: Blender에서 우리 리그로 옮긴다(루트 모션 처리, 발 미끄러짐 보정).
- 행인 세트: 걷기(속도 3종), 대기, 휴대폰, 대화 제스처, 앉기, 흡연 대체 동작(전자 담배풍), 놀라서 웅크림, 도망.
- 적 세트: 엄폐, 사격, 재장전, 피격(부위별), 넘어짐, 해킹당함(기존 경련 연출과 연결).

### 2-5. 군중 성능
- 행인은 Humanoid 대신 **AnimationController**를 쓴다(가볍다).
- 거리 LOD: 0~25스터드 LOD0(전체), 25~70 LOD1(삼각형 30%), 70~150 LOD2(10%), 150+ 임포스터(빌보드 이미지) 또는 숨김.
- 화면 안 행인 30명에서 데스크톱 60fps를 넘어야 한다. 넘지 못하면 LOD 거리를 줄이고 보고한다.

## 3. 1인칭 팔과 무기 (화면에 가장 크게 보이는 모델)
- **팔**: 사람 팔 메시 + 장갑 + 소매(재킷별 3종). 손가락 본까지 있는 리그를 쓴다. 지금 쓰는 소매·장갑 표시 규칙과 조준 시 소매 숨김 규칙을 유지한다.
- **사이버웨어 팔 4종**(블레이드, 파워암, 나노와이어, 런처, 전부 자체 디자인): 꺼내기 애니메이션에 맞춰 **움직이는 부품을 별도 메시와 본으로** 나눈다(장갑판 회전 → 칼날 전개 등). 진화 단계별로 외형이 달라진다.
- **총 12종**: 지금 `GunShapes.luau`의 각 총 성격을 유지하면서 Blender로 다시 만든다.
  - 정밀 모델 1만~2만 삼각형, 금속·폴리머·고무 PBR, 마모 표시, 조준경·탄창 표시는 발광 마스크로 한다.
  - **부착물 슬롯 위치와 손 위치(어태치먼트)는 기존 코드와 같게** 맞춘다.
  - 노리쇠, 탄창, 방아쇠, 해머처럼 움직이는 부품은 분리해 반동과 재장전 때 움직이게 한다.
  - `GunShapes`는 로딩 실패 시 대체용과 원거리 LOD로 남긴다.
- 1인칭 모델은 FOV 왜곡과 근거리 텍스처 해상도를 고려한다. 화면 가까이 오는 부분은 텍스처 밀도를 높인다.

## 4. 적(로봇·드론)과 차량
- **보안 로봇·드론**: 하드서피스(장갑판, 관절, 케이블, 센서 발광). 해킹당함 연출(스파크, 전기 아크)이 붙을 소켓을 넣고, 부위 분리 처치가 되게 만든다. 적 종류 추가는 승인 전이니 **기존 보안 로봇의 외형 교체만** 한다.
- **차량**: 자체 디자인 3~5종(세단, 택시 자체 도색, 밴, 트럭, 비행 차량). 유리·크롬·페인트 PBR, 실내 간단 모델, 발광 전조등과 후미등, LOD 3단.

## 6. 검증 (단계마다)
- **턴테이블 스크린샷**: 모델마다 정면, 측면, 45°, 클로즈업을 낮(day_golden)·밤(neon_rain) 조명으로 찍어 `docs/characters/<단계>/`에 저장한다.
- **거리 스크린샷**: 그래픽 패스의 고정 촬영 지점에서 행인과 차가 레퍼런스처럼 보이는지 나란히 비교한다.
- 수치 보고: 모델별 삼각형 수(LOD별), 텍스처 수와 해상도, 본 수, `validate.py` 결과, 화면 안 행인 30명일 때 fps, 메모리.
- 자체 평가: 레퍼런스 대비 "어색한 점 상위 5개"(예: 피부가 플라스틱 같음, 걸음이 미끄러짐, 머리카락 경계가 지글거림)와 다음 수정안.
