# 배틀로얄로 바꾸기

개발 세션(Opus)에 보내는 지시다. 2026-11-27 사용자 결정에 따른다. 다른 문서의 규칙(업로드 안전 0-2, 디자인 변경 금지, 단계마다 보고, 장소 저장 금지)은 그대로다.

## 0. 결정된 것
- **게임을 배틀로얄로 바꾼다.** 지금의 RPG(허브, 역할 선택, 상점, 수배, 시술소 성장)를 대체한다. 별도 모드가 아니다.
- **한 판 40명**(솔로). 모자란 자리는 봇으로 채운다. 처음 시험은 20명 안팎으로 한다.
- **전장은 매 판 큰 맵(16 km²) 안의 다른 자리**다. 인원에 맞춰 첫 원의 크기를 정한다(40명이면 약 4 km², 반지름 약 1,130 m). 맵 전체를 쓰지 않는다.
- **한 판은 약 12분 30초**(낙하 뒤부터 마지막 원이 닫힐 때까지 745초) + 대기와 낙하.
- **수위 제한 없음**(`Vitals.GORE = 4`), 플레이어끼리의 전투를 켠다. 등급은 다 만든 뒤에 사용자가 정한다.
- 차별점은 **사이버웨어**다. 총기 부착물 대신 사이버웨어 팔(블레이드, 파워암, 나노와이어, 런처, 손 레이저)을 전장에서 주워 단다.

## 1. 맵 현황과 걸림돌 (2026-11-27 조사)
맵은 크기와 지형이 이미 있다: 한 변 4 km, 회사 구역·부촌·빈민가·지하, 건물 약 5,200채, 큰 맵 0~4단계 완료. 배틀로얄에 없는 것은 아래다.

| 필요한 것 | 지금 상태 | 누가 |
|---|---|---|
| 들어갈 수 있는 건물 | 새 구역 건물은 전부 통짜 상자 충돌이라 못 들어간다 | 에셋 세션이 내부가 있는 건물을 만든다. 개발 세션이 놓는다 |
| 바닥 아이템 | 없다(무기는 역할 메뉴, 상자는 경험치만) | 에셋 세션이 아이템 모델과 배치 규칙을, 개발 세션이 줍기·인벤토리를 |
| 줄어드는 구역 | 없다 | `runtime/Zone.luau`(에셋 세션, 이미 있음) + 개발 세션이 벽 표시·지도·피해 연결 |
| 낙하 시작 | 없다(시작 지점 하나) | 에셋 세션이 수송기 경로·낙하 동작·낙하 장비를, 개발 세션이 연결 |
| 한 판의 흐름 | 없다(장소 하나, 이동 구조 없음) | 개발 세션 |
| 많은 인원 | 8명 가정, 스트리밍 꺼짐, 서버 1.2 GB | 개발 세션(3번 참고) |
| 다른 사람에게 보이는 차 | 차가 운전자에게만 보인다 | 개발 세션 |
| 봇 | 없다(행인·보안 로봇 로직만 있다) | 에셋 세션이 전투 봇 로직을 만든다 |

## 2. 한 판의 흐름
1. **대기**: 플레이어가 대기 구역에 모인다(기존 허브의 일부를 대기 구역으로 쓴다. 무기는 쓸 수 있지만 피해는 없다). 인원이 차거나 60초가 지나면 시작한다. 모자란 자리는 봇으로 채운다.
2. **전장 고르기**: `Zone.radiusFor(인원)`으로 반지름을 정하고 `Zone.pickStart(맵 범위, 반지름, 난수)`로 중심을 고른다. 지하 동굴만 걸치는 자리는 `blocked`로 뺀다.
3. **낙하**: 수송기(비행 차량 `flying_car`를 크게 쓴 것)가 첫 원을 가로지르는 직선으로 난다(높이 250 m, 초속 60 m). 플레이어는 원하는 때 뛰어내린다. 자유 낙하 뒤 높이 60 m에서 낙하 장비가 자동으로 펴진다. 원 밖으로는 뛰어내릴 수 없다.
4. **전투**: 모두 땅에 닿으면 `zone:start()`. 서버가 매 프레임 `zone:update(dt)`를 돌리고, 원 밖 플레이어에게 `zone:damage(x, z, dt)`만큼 피해를 준다. 사건(`phase`, `shrink_start`, `shrink_end`, `closed`)을 클라이언트에 보내 지도와 경고에 쓴다.
5. **끝**: 한 명(또는 한 팀)이 남으면 끝난다. 죽은 플레이어는 관전하거나 대기 구역으로 돌아간다. 순위와 처치 수를 보여 준다.
6. **다시 시작**: 전장을 치우고(아이템, 시체, 차) 1번으로 돌아간다.

처음에는 **장소 하나에서 판을 되풀이**한다. 대기실과 전장을 장소로 나누는 것(TeleportService)은 시험판이 돌아간 뒤에 한다.

## 3. 성능 (먼저 풀어야 하는 것)
- 40명과 봇이 한 서버에서 싸우려면 지금 구조(맵 전체를 한 번에 만들고 스트리밍이 꺼져 있음)로는 무겁다. 아래를 차례로 한다.
  1. **전장만 자세히**: 첫 원과 그 둘레 300 m만 실제 건물·충돌·아이템을 만들고, 나머지 맵은 실루엣으로만 둔다. 판이 바뀔 때 치우고 다시 만든다.
  2. **행인·교통·수배를 끈다.** 배틀로얄에는 군중과 보안 로봇 순찰이 없다(봇만 있다). 서버 군중 640명 계산이 사라진다.
  3. **충돌 상자**: 들어갈 수 없는 건물은 지금처럼 상자 하나, 들어갈 수 있는 건물만 벽·바닥·계단 충돌을 준다.
  4. 그래도 모자라면 스트리밍을 켜는 방법을 보고한다(지금은 실행할 때 코드로 만들기 때문에 켜지 않았다).
- 목표: 전장 안에서 실제 클라이언트 기준 40프레임 이상, 서버 메모리 800 MB 이하. Studio 수치만으로 판단하지 않는다.

## 4. 없애는 것과 남기는 것
| 없앤다(숨기고 끈다. 코드는 지우지 않고 설정으로) | 남긴다 |
|---|---|
| 역할 선택 메뉴, 상점 32곳, 경험치 상자와 단말기, 수배와 보안 순찰, 행인 군중, NPC 교통, 죽음 벌칙 없음 설정 | 1인칭 조작과 총기 감각, 무기 17종, 사이버웨어 팔 5종과 손 레이저, 해킹(전장의 포탑·카메라·문에), 피해·사망·수위(`Vitals`), 운전(`Driving`), 큰 맵과 건물, 낮·밤과 비 |

- 사이버웨어 성장(시술소)은 판 밖의 성장으로 남기지 않는다. 모든 플레이어가 같은 조건으로 시작한다. 꾸미기(옷, 사람 모습)만 판 밖에 남긴다.
- 사람 모습은 지금의 10명에서 고른다(나중에 늘린다).

## 5. 에셋 세션이 만들어 보낼 것 (요청하지 않아도 온다)
| 묶음 | 내용 |
|---|---|
| 들어갈 수 있는 건물 | 문·창·계단·방이 있는 건물 6~8종(1~4층). 옥상에 올라갈 수 있다. 아이템이 놓일 자리 표시(`loot_*` 관절)가 들어 있다 |
| 바닥 아이템 | 탄약 상자, 방탄복 3단계, 헬멧, 회복 주사기·붕대, 수류탄 묶음, 사이버웨어 팔이 든 상자, 보급 상자 |
| 낙하 | 수송기(크게 만든 비행 차량), 낙하 장비(펴진 것·접힌 것), 낙하·착지 동작 클립 |
| 구역 표시 | 원의 벽에 쓸 재질(글자 없는 무늬) |
| 로직 | `Zone.luau`(있음), 아이템 표와 배치(`Loot.luau`), 한 판의 상태 기계(`Match.luau`), 전투 봇(`Bot.luau`). 전부 Lune 테스트와 함께 |

## 6. 작업 순서
단계마다 멈추고 보고한다.

| 순서 | 할 일 |
|---|---|
| 1 | **설계 보고(코드 없음)**: 이 문서를 지금 코드에 어떻게 얹을지. 끌 서비스, 새 서비스, 판 되풀이 구조, 전장만 자세히 만드는 방법, 위험한 곳. 승인받는다 |
| 2 | `Zone.luau`를 편입하고(테스트 204개), 원의 벽 표시·지도·원 밖 피해를 넣는다. 혼자서 원이 줄어드는 것을 처음부터 끝까지 본다 |
| 3 | 대기 → 전장 고르기 → 낙하(임시로 높은 곳에서 떨어지기) → 전투 → 끝 → 다시 시작의 뼈대. 무기는 임시로 바닥에 흩어 둔다 |
| 4 | 플레이어끼리의 피해, 죽음, 관전, 순위 |
| 5 | 들어갈 수 있는 건물과 바닥 아이템(에셋이 오면) |
| 6 | 낙하(수송기, 낙하 장비), 차를 다른 플레이어에게 보이게 |
| 7 | 봇으로 자리 채우기 |
| 8 | 성능(3번)과 실제 기기 시험 |

## 7. 하지 않는 것
- 다른 게임의 이름, 지도, 화면 배치, 소리, 고유한 물건을 따라 하지 않는다. 장르의 규칙(줄어드는 구역, 낙하, 줍기)만 쓴다.
- 지금 코드를 지우지 않는다. 설정으로 끄고, 되돌릴 수 있게 둔다.
- 피나 절단면을 그린 그림을 올리지 않는다(0-2의 G).
